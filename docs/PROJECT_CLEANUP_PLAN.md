# Project Cleanup and Final Decomposition Plan

## Цель

Завершить frontend-декомпозицию, привести структуру проекта к понятным
архитектурным границам, удалить только доказанно неиспользуемые файлы и после
этого подготовить воспроизводимый Docker-запуск. Все изменения выполняются
маленькими срезами с сохранением текущего поведения.

## Неподвижные контракты

До завершения сквозной проверки нельзя одновременно менять:

- UI и пользовательский сценарий планировщика;
- порты и WebSocket-контракты;
- route, telemetry и runtime-command форматы;
- координатный контракт;
- алгоритмы движения, Mapping Survey и объезда препятствий;
- форматы файлов в `web_state`.

Удаление файла разрешается только после проверки импортов, runtime-вызовов,
сборочных конфигураций и документации. Перемещения выполняются отдельно от
изменения поведения.

### 2.2 Целевая структура

```text
bridge/             bridge composition, protocol, servers, solver, telemetry
docker/             Dockerfiles и контейнерные скрипты
docs/               актуальная архитектурная и пользовательская документация
native/             C++ route solver
public/             статические frontend-ресурсы
scripts/            проверки и служебные команды
shared/             межпроцессные контракты
src/
  app/              композиция приложения и routing
  components/       общие UI-компоненты
  features/planner/ planner hooks, model, services и UI-секции
  pages/            тонкие страницы
  lib/              только действительно общие независимые библиотеки
webots/
  controllers/      Webots controller и C-модули
  worlds/           Webots worlds и необходимые assets
web_state/          runtime state; в Git хранится только `.gitkeep`
```
